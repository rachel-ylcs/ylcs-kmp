    Kotlin Multiplatform · Compose Multiplatform

    一套 Kotlin 代码
    构建全平台应用

    Rachel 将跨平台入口、共享界面、应用服务、客户端与原生服务端通信、页面导航、平台视图与桌面分发组织为模块化体系，并提供统一的类型安全 DSL。框架能力按模块发布，应用可按实际目标引入依赖。

    KMP 共享核心与目标配置
    CMP 跨平台界面体系

    框架能力

    核心能力与模块边界

    以下能力均由独立模块提供。目标平台、依赖导出与资源范围由模块构建脚本定义，应用可按需引入。

    多平台目标

    构建模板支持 Android、iOS、JVM Desktop、Web，以及 Windows、Linux、macOS 的 Kotlin/Native 目标。模块按需启用目标。

    共享源集

    原生构建路径

    Kotlin/Native 生成平台二进制，桌面端不依赖 JVM。窗口、媒体、文件与平台句柄由对应所有者创建和释放。

    Kotlin/Native

    类型安全 DSL

    模块、源集、依赖、接口、导航与构建产物通过结构化 DSL 声明。类型与导出关系在编译期检查。

    编译期约束

    模块化依赖

    框架按 core、foundation、compose、cs 与 platform 分组。应用只引入实际使用的模块，依赖方向保持单向。

    按需依赖

    前后端共享契约

    接口、资源路径、文件参数与 WebSocket 入口在共享模块中声明，客户端与服务端使用同一套类型与线格式。

    共享类型

    构建与发布约定

    统一构建模板、目标开关、运行目录、产物注册与发布配置。新增模块可按固定步骤接入构建与测试流程。

    构建约定
    分层结构

    模块分层与依赖方向

    上层模块依赖下层契约；平台差异停留在源集边界。框架模块不依赖业务应用。

    查看模块全景 →
    模块分层 / 依赖方向
    App 业务模块 Gallery Modern Navigation Server
    UI theme ui screen app platform-view components
    C / S cs:core client-engine server-engine mysql · redis
    Core core foundation filesystem network startup parsers
    Native ffi posix · win32 native-compose bridge plugin
    依赖方向：App → UI → C/S → Core → Native；手写指南与生成页面分开维护。
